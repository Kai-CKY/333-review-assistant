管理者于 2026-10-04 确认页面和数据设计，授权代码 review、上线与原格式数据迁移，无需再次确认发布。原格式及原图备份放在管理者本机 `.data/local-backups/`。

## 实现与 review 结果

- 正式管理员首页进入 `/console/`，保留 `/study` 背诵与自评入口。工作台展示实时会话、归档、备注、档案、固定两人绑定、横向上传时间线及复习日历。示例体验只保留在本地 prototype。
- `/api/console`、原图及校正接口要求管理员登录，继续检查请求来源。校正采用版本比较，保留初始转写与旧版本；已入库原文创建新资料修订，让 Agent 读取新文字。校正不替学习者作答、自评，不重置复习状态。
- 数据采用已批准的独立表名称与字段。新增 `runtime_fragments` 分行保存尚未类型化的辅助字段；`migration_originals` 保留迁移时每个实体的不可变原始快照。业务读取使用当前字段，所有写入在 SQLite 事务内完成。旧整体 JSON 不作为运行数据或查询来源。
- 迁移完整往返比较原数据，唯一有意删除的是管理者确认的旧演示知识点及关联示例状态。知识 ID、上传时间、真实状态、会话范围、当前及归档消息、处理草稿和渠道状态均保留；附件逐文件比对哈希。
- 新学上传次日首复，发现遗忘当天先复习。图片附言中的“新学／今天学习／遗忘”等明确用途进入对应规则；未表达学习用途的资料先记录，可由管理员在未进入复习的上传记录中设置用途。后续按实际四档自评计算。日历预测不写复习日志。
- 每日提醒按北京时间和持久化设置运行，默认 09:00，可在工作台修改或暂停；当天有到期或逾期内容才发送，持久记录发送状态以防重启重复。提醒不改变复习日期、掌握度或完成记录。

Review 修复了 demo 与正式仓储不兼容、样板固定日期、管理员原权限阻止校正、修改缓存被资料同步覆盖，以及页面图片字段不一致等问题。保留旧 JSON/早期 SQLite 的读取兼容用于离线工具与既有测试；正式 Compose 强制使用新格式。

## 发布和回滚

1. 在功能分支提交，推 GitHub；该提交的 CI 必须通过。依赖不变，本次使用 GitHub CI 构建、测试并交付镜像，本机和旧服务器均不执行构建。CI 在公开仓库的 `image-COMMIT` 预发布中保存源码镜像和 SHA256SUMS，不包含运行数据或凭据。
2. 使用同一提交构建并验证镜像；在隔离测试目录、独立数据库上验证管理员 API、原图、校正、重启和健康。测试实例的飞书保持关闭。
3. 记录原提交、镜像 ID 和 Compose 原件。短暂停止正式实例取得最终快照，下载原 JSON 与附件到本机，再用 `scripts/migrate-relational.mjs --source ... --manifest ... --target NEW.sqlite` 转换。校验通过后把 SQLite 放入正式 runtime-data；旧 JSON 保留为原格式备份，不再读写。
4. 快进正式 `main` 到同一已验证提交，交付已构建镜像，执行 `docker compose up -d --no-build`。配置与图片目录留在正式实例，不复制测试配置或数据库。
5. 检查容器 healthy、匿名 401、管理员登录和 `/api/runtime` 的提交／`relational-v1`／飞书 connected，以及工作台、图片与数据库完整性。确认只有正式飞书连接开启。
6. 失败时恢复原 Compose、原镜像和原提交，重新使用最终原格式 JSON。上线后已有新的学习或消息写入时，先备份新库并按 `readDatabaseFile` 导出新格式完整领域状态，不能直接用旧备份覆盖新记录。

原始快照和发布记录不入 Git，不输出密码、API Key、Cookie 或完整学习内容。线上 Agent 的后续动作由管理者再明确指示；发布验证不代发学习消息或代选自评。
