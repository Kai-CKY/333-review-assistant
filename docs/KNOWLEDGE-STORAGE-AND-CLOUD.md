# 知识库随 Git 保存与云端修改

## 已落地的 Git 保存方式

`.gitignore` 现在放行 `.data/knowledge-export/`，保留对其余 `.data/` 运行文件的忽略。当前完整知识库快照已经导出，其中有：

- 已保存知识及全部修订版本、确认来源、待核验标记。
- 图片任务、两次OCR原始结果、对齐稿、核验记录、来源链接、知识修改事件。
- 原图，以及知识文档归档目录中的文字稿、原始测试稿、单独保留的部分核验结果。
- 知识所属的应用、群或私聊、话题标识及必要的会话编号，以便恢复隔离边界。
- Web题库的知识点定义；不包含掌握度和复习记录。

不导出用户档案、普通群聊/私聊历史、长期个人备注、答题/复习记录、运行日志、登录二维码或环境密钥。知识条目自身的确认人、群标识和原图仍属于快照内容；知识库仓库宜保持私有。

`manifest.json` 保存结构化记录和文件校验值；`blobs/` 按SHA256存储原图及归档文件。这样复制整个导出目录就能恢复知识库，无需依赖本机Temp图片路径。旧内容块可能保留，以避免导出中断破坏上一份快照。快照是知识数据备份，不是全部会话与学习进度的备份。

修改忽略规则不会自动创建Git提交，也不会自动推送。普通提交时应包含导出目录。后续数据发生变化后，重新导出再提交，才能把新版本带上。Git忽略规则对已跟踪文件另有行为，参见[Git官方说明](https://git-scm.com/docs/gitignore)。

## 导出与恢复

在项目根目录导出当前知识库：

```text
npm run knowledge:export
```

默认读取`.data/review-assistant.json`；自定义数据路径时通过进程环境`DATA_FILE`，或参数`--database`指定。脚本不会自动加载`.env.local`。示例：

```text
npm run knowledge:export -- --database /data/review-assistant.json
```

首次部署云端时，在启动Agent之前，将快照恢复到一个**尚不存在**的数据库文件：

```text
npm run knowledge:restore -- --database /data/review-assistant.json
```

恢复会同时写入同目录的`knowledge-assets/`、`knowledge-library/`；校验所有图片/附件哈希，保留版本和范围隔离。恢复不重放未完成的付费请求，也不把旧会话草稿改成新会话可确认。目标数据库已经存在时，恢复命令拒绝覆盖；这能避免代码发布把云端新知识覆盖成Git里的旧快照。更换飞书应用、群或话题后，不能依靠恢复自动跨范围共享，需另行授权迁移范围。

生产运行期间不要由外部脚本直接改写数据库。当前仓储只支持一个服务进程写入。快照导出读取数据库，不修改在线数据；首次恢复则应在目标服务启动前执行。完整灾备还需备份运行数据库及其图片/归档目录，知识快照不能恢复聊天、个人记忆与学习进度。

## 云上的 Agent 能否自行修改

**可以。** 本机Codex是开发/维护工具；部署后的Agent是独立运行的服务。飞书消息交给云端服务，它调用模型及核验工具，再由服务的知识库模块写入云端数据文件。我不在线、电脑关机，都不影响已正常运行的云端服务处理消息。

当前写入路径为：

```text
飞书配置群中的图片
  → 两次独立识读 → 对齐 → 网络核验 → 返回带编号和版本的草稿
  → 羊羊确认 → 云端保存新版本（历史版本保留）

羊羊的修改建议/完整修改稿
  → 按编号和版本定位 → 生成修订 → 重新核验 → 确认后保存
```

模型生成的文本不能直接授权写入；发送者身份、范围、版本、是否送达及核验证据由服务检查。

| 当前操作 | 结果 |
|---|---|
| `修改 KP-b8762b08 v1：第二条改成……` | 生成新草稿并核验；旧的已保存版本仍然有效，需再确认 |
| `确认 KP-b8762b08 v2` | 版本匹配且条目核验通过后保存 |
| `确认已核验部分 KP-b8762b08 v2` | 仅保存已核验条目，未核验条目标明排除 |
| `修改并保存 KP-b8762b08 v1：……` | 视为明确修订并保存指令；先送达修订稿，再由服务检查后保存；核验失败仍不保存 |
| `这里应该改成……` | 只有当前范围能唯一定位一份草稿且发送者有权限时，才转为修改建议；不会自动视为确认 |

这些示例中的版本需以实际最新草稿为准。权限当前绑定羊羊的飞书open_id；昵称、自称身份、模型判断不能授予权限。群、私聊和话题不共用会话上下文。图片知识工作流目前接在配置群的处理器；私聊尚未接入相同的图片知识写入流程。`/new`或重置后的会话不能直接确认、修改重置前的旧草稿；已保存知识仍可在同范围查询，跨会话重新开启修订还需补充工作流。

2026-09-18的生物学资料是项目用户在Codex明确要求“先这样保存”的一次本地存档导入，保留`unresolved`及授权来源。这没有扩大群聊成员权限，也没有把“未核验按现状存档”实现成飞书中的通用命令。

## 推荐的云端数据关系

- Git：程序、说明、某个时间点的完整知识快照。
- 云端持久存储：运行中的最新知识、会话和学习数据；以它为准。
- 云端备份：定期备份运行数据库和附件；需要同步回Git时另行导出快照、审核、提交。

云端写入不会自动回传本机，也不会自动提交到Git。发布新代码也不应自动恢复旧快照。Docker持久卷可使数据独立于容器生命周期，见[Docker官方说明](https://docs.docker.com/engine/storage/volumes/)。

我目前未连接云服务器，因此无法直接读取或修改将来的云端实时数据。需要维护时，可以通过你授权的远程连接、管理接口或下载的备份处理；日常知识修订由云端Agent完成，不依赖这些维护入口。当前没有带鉴权的远程知识管理接口，也未配置自动备份/自动Git同步，不应把这些描述为已经上线。

当前JSON仓储适合单实例验证，不支持多实例并发写。上云前还需配置持久卷、备份和恢复、鉴权及运行守护；现有HTTP接口未鉴权，不能直接暴露到公网。图片逐渐增多时，Git体积会增长，可再将图片移到对象存储或Git LFS，但迁移前不能只保留本机图片路径。
