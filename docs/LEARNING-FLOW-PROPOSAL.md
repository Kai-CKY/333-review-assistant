# 学习流程与已确认规则

2026-09-23 更新：用户已确认“自己是管理员、不参与学习”“上传即表示以前学过、当天发现遗忘”。本文件替代此前首次学习日期待填的提案。

## 已实现：知识、回忆与时间线

Web 和飞书读取运行库中的最新已保存修正版，知识索引和普通问答不显示版本号。内部仍保留修订历史、草稿确认版本及反馈证据快照，防止误确认旧草稿或改写历史。修订中的未确认草稿不替换已保存内容。

羊羊在网页打开任务 → 写下回忆（想不起来也可如实记录）→ 保存答案 → 查看入库参考与异步结构反馈 → 自选四档等级 → 显示下次复习日。模型不可用时，答案和排程仍可保存。知识点展开后显示“发现遗忘 → 每次自评 → 下次日期”的事件时间线。持久存储仍为单 JSON 文件，并非 SQL 数据库。

你使用管理员账号查看羊羊的任务、进度、完成记录与时间线，不创建你的学习档案。Web 管理员由 WEB_ADMIN_USERS 指定；飞书管理员由 FEISHU_OWNER_OPEN_ID 指定。后台拒绝管理员的作答、自评和学习卡片写入。

## 已实现：上传日是遗忘起点

- 例如 9 月 23 日上传，默认该资料以前学过，9 月 23 日发现遗忘；全部相关知识点在 9 月 23 日待复习，不受普通每日 5 项上限隐藏。
- 不伪造过去某一天的首次学习日期；firstLearnedOn 保持空，previouslyLearned 为真。
- 优先使用原消息上传时刻，其次原草稿创建时间；旧资料缺少这些字段时以文档最初创建/首次保存时刻兼容迁移。完全没有日期则标为待确认，不拿服务器今天冒充。日期按 Asia/Shanghai 计算。
- 入库确认晚于上传时，仍保留上传日期；上线时已经过去的任务表现为待补复习。2026-09-18 的旧存档不会因为 9 月 23 日部署而重写成新上传。
- 本规则只应用于已保存、获准进入羊羊知识范围的条目；未确认草稿不参与。
- 资料修订、页面刷新和进程重启不重新触发遗忘、不覆盖已经完成的复习。已有上传日之后的实际复习记录优先保留。
- 既有待核验存档可自主回忆，仍标为待核验，不能作为标准答案。这不扩大飞书知识入库的确认权限。

## 已实现的排程与下一步选择

目前是可复现的四档间隔算法，不是正式 FSRS，也不是测得的个人真实遗忘概率曲线。遗忘后第一次自评的间隔：完全想不起来 1 天、很吃力 1 天、基本掌握 3 天、很熟练 5 天。以后随实际自评调整；再次想不起来一律回到次日，其他等级按上一间隔的 1.2 / 2.5 / 3.8 倍取整。

因此 9 月 23 日“基本掌握” → 9 月 26 日到期；“完全想不起来” → 9 月 24 日到期。日期从实际完成本次自评的那天计算。没完成当天复习，则继续待办，不能当作已经学会。资料型知识点不会仅因掌握度较低而在尚未到期时提前重返每日任务。

网页已有可视待办、每 30 秒刷新、下次日期和事件时间线；飞书 /今日、/进度、/薄弱、/记录 可随时查询。群聊与私聊分开，群里不注入私聊学习记录。当前没有每日主动发送的到期提醒，现有一次性入群提问也不能当作每日提醒。

建议后续由用户拍板：先实现每日一次飞书汇总，建议 20:00（北京时间），只发给羊羊；提醒任务持久化、按日期去重、失败可见，完成后不重复催促。正式 FSRS 的选型及新增依赖、预测曲线另行评估。本次不新增运行时依赖，不替用户创建持续监控或自动发消息任务。

## 线上验收与观测

本地功能测试不等于线上验收。发布后需用羊羊与管理员两个真实账号完成 Web 登录、作答保存、刷新/重启持久化、飞书身份及群/私聊隔离检查。先保留 Nginx Basic Auth，应用验收后再撤除。

进程存活看 Docker healthcheck；端到端可用性还需监测公网登录页/API 状态、真实登录后的任务读取和模型/消息失败日志。建议先使用现有云监控的 HTTP 探测及日志告警，再以独立测试数据运行合成学习流程；不能把生产学习数据当作定时探针。/api/health 只代表进程存活，不能证明模型调用与飞书长连接正常。
