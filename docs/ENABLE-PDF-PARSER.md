# PDF 改为离线解析

2026-09-26：在线 MinerU 方案已撤回。生产 Compose 只有学习应用，不构建解析器、不下载 OCR 模型、不提供网页或飞书 PDF 上传。旧 `PDF_PARSER_URL` 配置不会重新启用解析。

## 当前流程

1. 开发电脑解析、整理 PDF，保留原件、页码和引用位置。
2. 人工核对关键文字和关系，以 `materialKind: textbook` 导入本地库，不生成羊羊的遗忘事件。
3. `knowledge:export` 生成知识快照，检查附件、权限范围和版本。
4. 单独传输资料快照到服务器，先运行 `knowledge:merge` dry-run；停止应用、备份并核对无冲突后再 apply。禁止用资料快照覆盖学习运行库。
5. 网页选择学习范围，维护答案要点和依据，使用已有教材的原页回查。

代码、教材快照、运行数据是三种交付物。代码上线不会自动导入本机新解析的教材。

## 可选本地工具

`apps/pdf-parser/` 保留给开发电脑离线批处理复用。需要时显式运行：

```text
docker compose -f compose.pdf-offline.yaml up -d --build
docker compose -f compose.pdf-offline.yaml stop
```

仅监听 `127.0.0.1:8010`，会占用本机磁盘/内存并下载模型，不应在生产服务器执行。现有离线整理脚本可继续复用；线上不依赖此服务。

历史原件、解析结果、知识点和学习记录保留，不重启遗留解析任务。旧 `/api/pdf-imports` 登录后返回 410 和离线处理说明；已入库教材的原页读取有效。尚未入库草稿需在本地核对，不会随代码升级自动发布。
