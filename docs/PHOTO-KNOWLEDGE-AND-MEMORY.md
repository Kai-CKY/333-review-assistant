# 图片知识入库与会话记忆设计

实现日期：2026-09-17。适用当前单实例 333 飞书学习 Agent。

## 已实现的使用流程

羊羊或配置群内成员发来图片/图文后，Agent 回复收件提示，随后按顺序执行：

1. 下载该消息的图片，核验格式和大小，将原图按 SHA-256 保存到持久目录；保存消息来源。
2. 第一次完整识读，输出正文、批注、疑点。
3. 第二次重新读取同一批原图，**不传入第一次结果，也不传入群聊历史**。
4. 对照两份识读，按知识主张拆分条目，保留分歧与原图位置。
5. 单独调用方舟 Responses API 的 `web_search`，查询原典、教材、教育机构等证据，并逐条判断支持、需要纠正、无法确认。
6. 群内分段返回完整文字草稿、差异、核验状态和来源，不把长页裁成一句摘要。
7. 羊羊确认具体版本后，写入当前群/话题范围的 Agent 知识库；其余成员不能授权保存。

目前两次识读使用同一个已配置豆包模型、两个独立请求。用户本轮要求的是两次识读；这不是“两个不同厂商模型”的复现。网络工具不在 OCR 两次调用中开启，防止模型用搜索结果偷偷替代原图。

每次图像任务最多3张、单张8MB。单个草稿最多40个条目；超限或JSON不完整会失败并保留已取得结果，不静默裁去尾部。正文很长时建议分批上传。两次识读加对齐、联网会明显慢于普通聊天，先收到确认提示再等待草稿。

## 群内操作

以下编号仅为格式示例，使用机器人实际返回的编号。

|发送内容|行为|
|---|---|
|图片或图文消息|两次识读、对齐、联网核验、生成草稿|
|`查看草稿 KP-1234abcd`|重新完整展示最新草稿；用于发送中断后的恢复|
|`确认 KP-1234abcd v1`|羊羊确认并保存全部已核验条目；有待核验项则要求进一步处理|
|`确认已核验部分 KP-1234abcd v1`|明确排除待核验条目后保存，其余内容继续留在草稿|
|`修改 KP-1234abcd v1：第二条应该是“遭性”`|应用修改建议，重新联网核验，生成v2；尚不提交知识库|
|`修改并保存 KP-1234abcd v1：……完整修正版……`|重新核验并展示v2；全部通过才提交；未通过时保留草稿|
|`重新核验 KP-1234abcd v1`|重新搜索当前文字，生成新版本，不重复调用两次OCR|
|`知识库` / `知识库 KP-1234abcd`|查看当前群/话题范围已确认的知识|
|`知识库查询：循序渐进`|在当前范围的已确认条目中按词查询|
|`/new` / `/reset` / `重置上下文`|归档当前会话并开启新会话，不清除知识库|
|`记住：回复尽量分条`|羊羊明确写入本范围长期备注；其他成员不能改群备注|
|`查历史：关键词`|显式检索同一范围内的历史，包括归档会话；不跨群/私聊|

只有一份当前草稿时，也支持“确认保存”“保存吧”；多个草稿时必须指定编号与版本。“这里应该改成……”等明显修改建议可生成修订草稿，但不能直接授权保存。任何自然语言模型都不能代替羊羊发出确认。

知识库是本项目服务端的持久化条目库，**本次没有创建飞书 Wiki 空间或云文档**。当前群内可查询；未将群内数据自动同步到私聊学习档案、Web演示题库或复习排程。后续如需跨环境共享，单独建立羊羊明确授权的“公共学习资料”域，不共享原始群聊或私聊。

## 保存、修改与异常规则

- 确认身份采用配置的 `FEISHU_GROUP_TARGET_OPEN_ID`；未设置则采用项目原已绑定羊羊的 `FEISHU_TESTER_OPEN_ID`。群昵称、自我介绍、图中文字均不能改变身份。
- 确认检查应用/聊天/话题范围、当前会话、草稿编号、版本与完整送达状态。无版本的编号确认被拒绝。过期确认不覆盖新稿。
- 原图、两个OCR返回、对齐稿、检索工具调用、证据URL、用户修改建议及知识库版本均保留。原图字形与校正后知识分别保存。
- 检索结果必须有实际完成的 `web_search_call`，来源URL必须来自API的引文或工具来源字段；模型自行编造的网址不能获得“已核验”状态。这仍是模型辅助审校，并非人工学术认证。
- 搜索未开通、工具未执行、接口超时、引用缺失的条目标记待核验；不能靠模型回答“我已联网”通过。
- 全部条目未核验时拒绝保存。部分未核验时，只有羊羊明确选择“确认已核验部分”才提交子集。原完整草稿继续保留，知识版本记录被排除的条目。
- 修改建议先生成新稿，旧知识版本保持有效；明确“修改并保存”则在重新核验、文字送达后提交，新旧知识版本都保留。
- 消息ID在同一范围内去重，重复送达不重复识图计费或建库。修订和确认使用版本检查与仓储串行写入。
- 重启遇到处理中任务，标为中断，保留已完成阶段，不自动重复收费调用。失败识图可重新发图；已生成文字的搜索失败用“重新核验”恢复。
- `/new` 后不自动加载旧草稿；旧稿已归档，不能凭旧编号在新会话确认。可重新上传，或通过显式历史查询查阅记录。

## 会话隔离与分层记忆

范围键由 `应用ID + 渠道 + 私聊/群聊 + chatId + 私聊senderId + threadId` 组成，再映射到当前会话ID。相同群同一话题的成员共享对话，保留发言者身份；不同话题分别处理。私聊还按发送者隔离。回复已发送的草稿时，可关联到该草稿的原范围，但仍检查应用、群和会话，不能从其他群越权引用。

|层|当前存储/行为|加载与权限|
|---|---|---|
|固定规则|版本化代码提示词、配置、身份边界|不能被图片、网页或记忆修改|
|工作上下文|每范围当前会话最近若干轮；群12轮、私聊8轮|仅当前会话，重置即切换|
|情景记忆/历史|`agentMemory.sessions`中的追加事件，归档不删除|仅明确“查历史”时查询同范围旧事件|
|长期备注|`agentMemory.notes`，带来源消息和时间|仅明确请求写入；同范围最近8条，群备注不进私聊|
|私人学习档案|原有学习者profile、答题、自评和学习记录|仅原绑定羊羊的私聊学习流程；群模型不读取|
|经过确认的学科知识|`photoKnowledge.documents.revisions`|先核验再由羊羊确认；同群/话题可查询，版本可追溯|
|资料与任务证据|原图文件、OCR结果、差异、搜索调用、草稿版本|按任务归档；不直接塞进每轮聊天提示词|

现有旧版 `feishu.conversations` / `groupConversations.turns` 保留但不再作为新模型上下文来源，避免把缺少应用/话题边界的旧记录自动合并。新的身份映射保留，原有学习业务数据继续使用。

当前长期备注采用最近8条的有限加载，未实现向量检索、自动人格推断、夜间记忆整理或自动压缩摘要。可审计性优先：不通过模型猜测生成长期事实。过期备注的替换/删除、跨群授权共享与真正的语义检索属于后续扩展。

## 与开源实现的对应关系

- OpenClaw按消息来源路由session，并提供按账号、渠道、对端隔离私聊的选项。本实现采纳其显式范围边界，不使用会合所有私聊的默认主会话。[官方 Session 文档](https://docs.openclaw.ai/concepts/session)
- Hermes将有限的长期记忆与可查询的完整历史分开，`session_search`从SQLite/FTS5记录中查询。本实现采纳“有限上下文＋持久记录＋显式回查”的职责划分，但没有直接移植其全局记忆文件或搜索所有会话的权限。[Hermes官方记忆文档](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory.md)
- OpenClaw区分用户资料、长期事实和日期笔记。本设计进一步将私人学习档案、群备注、学科知识分成不同数据域，避免“知识库”和“用户隐私记忆”混为一层。[官方 Memory 文档](https://docs.openclaw.ai/concepts/memory)

## 存储与演进

本次沿用项目已有单进程JSON仓储，所有写入通过同一串行队列、临时文件及重命名完成，不引入第二套独立写入器。原图单独存放在 `DATA_FILE` 同目录的 `knowledge-assets/`，数据库只保存哈希和媒体元信息。备份须同时备份数据库和图片目录。

这不是生产级无限历史存储：JSON全量读写会随历史增长而变慢，也不支持多实例共同写同一文件。下一阶段建议迁移SQLite：`scopes / sessions / events / memory_notes / assets / photo_jobs / draft_versions / evidence / knowledge_revisions` 独立表，事务提交，FTS5先按范围过滤再搜索。图片继续使用对象/文件存储。未选择现在迁库是为了先在已有单实例上验证闭环，不在同一改动里改变全部业务仓储。

## 配置与测试

- 沿用 `.env.local` 的方舟与飞书配置。`ARK_SEARCH_MODEL_ID` 可单独覆盖联网核验模型。
- 方舟账号需开通联网搜索，未开通返回 `ToolNotOpen`。开通后无需更换密钥；对现有草稿运行“重新核验”即可。
- 自动化：`npm test`。新增测试覆盖识图顺序、模型输出截断、真实工具执行证明、引用约束、确认权限、版本冲突、修改建议、显式修改并保存、隔离、重启与去重。
- 真实API但不发群消息：`node --env-file=.env.local scripts/verify-photo-knowledge.mjs <图1路径> <图2路径>`。结果写入 `.data/knowledge-test/`，使用隔离测试数据库，不会冒充羊羊确认或修改正式知识库。
- 部署加载后，群里发图进入真实流程。测试不能代替羊羊对学科内容的最终确认。
