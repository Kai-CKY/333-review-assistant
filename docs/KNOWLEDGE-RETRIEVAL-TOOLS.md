# 知识点检索工具：契约与调用流程

日期：2026-09-26。状态：本文保留完整 V2 目标契约；实际参数、限制和路径见 [本次实现说明第 3 节](KNOWLEDGE-V2-IMPLEMENTATION.md#3-检索工具与上下文)。本文 AccessContext、全部过滤项、索引状态和返回字段未全部实现，不应直接当作当前 API 文档。主方案：[知识库 V2 设计](KNOWLEDGE-V2-DESIGN.md)。示例 ID、书名、页码为虚构数据。

## 1. 工具与 Agent 的关系

工具是一段受控后端程序：校验权限，查询数据库/索引，返回结构化资料。模型负责解释这些资料。知识库不会整库挂进系统提示，也不会因为文件位于 OSS 就自动成为模型可检索知识。

第一版采用后端编排：

```text
收到问题 → 判断场景 → 调用检索/读取服务 → 控制上下文 → 模型回答 → 核对引用
```

既有 `searchSavedItems()` 将由统一 RetrievalService 替代。它既可以被普通 Node.js 业务代码调用，也可以将来包装成模型工具；工具名称不是承诺当前模型 API 已经接入 function calling。

初期不让模型控制无限检索循环。场景已知时直接走固定流程；用户只是打招呼不查教材。学科问题不因简单关键词路由漏判就永远跳过检索：意图不确定时允许一次只读检索，仍无依据则说明不足或询问范围。

## 2. 统一运行上下文

```ts
type AccessContext = {
  actorId: string;                 // 由已认证会话确定
  role: 'learner' | 'admin';
  allowedLibraryIds: string[];     // 服务端授权结果
  allowedScopeKeys: string[];
  learnerId?: string;              // 仅获准读取个人状态时存在
  channel: 'web' | 'private' | 'group';
  requestId: string;
};
```

`AccessContext` 不作为模型自由填写的工具参数。群聊上下文不能通过工具参数变成私聊权限。检索、回读片段、图谱、缓存读取都再次执行相同范围过滤；按未授权 ID 读取返回不可见，不泄露文件名或摘要。

工具结果统一带 `retrievalId`、`indexVersion`、`outcome`、`truncated`、`warnings`。无命中、索引待就绪、服务故障分别返回 `no_match`、`not_ready`、`unavailable`，不能全部解释为“教材里没有”。授权失败在边界层处理，不返回候选内容。

## 3. search_knowledge：找相关知识或教材

**职责：返回候选和短摘录，不生成最终答案，不修改任何知识。**

```ts
searchKnowledge(ctx, {
  query: string;                        // 必填，最长 500 字符
  purpose: 'qa' | 'photo_check' | 'reference_lookup'; // 后端场景固定
  target?: 'all' | 'points' | 'textbook_chunks';
  filters?: { subject?: string; sourceIds?: string[]; chapterId?: string };
  limit?: number;                        // 默认 5，服务器上限 8
});
```

模型如提供 filters，只能缩小服务器授权集合；不能通过 sourceIds 扩权。`purpose` 不是授权开关，也不能把待审核资料提升为 reviewed。

返回示例（摘录内容省略，仅演示结构）：

```json
{
  "retrievalId": "ret-demo-01",
  "indexVersion": "fts-demo-1",
  "outcome": "matched",
  "hits": [
    {
      "kind": "textbook_chunk",
      "id": "chunk-demo-042",
      "pointId": "point-demo-008",
      "title": "最近发展区",
      "excerpt": "此处为从原文截取的相关段落……",
      "evidenceStatus": "reviewed",
      "source": {
        "id": "book-demo-a",
        "revision": 1,
        "title": "教材 A（示例）",
        "edition": "待核对版本",
        "chapterPath": ["示例章节"],
        "anchors": [{"partId": "part-demo-1", "pdfPage": 42, "printedPage": null}]
      },
      "matchedFields": ["title", "body"],
      "hasMoreContext": true
    }
  ],
  "truncated": false,
  "warnings": []
}
```

`pointId` 可为空：教材中有相关原文但尚未建立知识点，仍应找到。point 命中会提供知识点摘要、答案审核状态和证据 ID；该 point 下的所有原文不会一次全部返回。关系分数只用于排序/调试，不当作知识正确性概率。

内部处理：

1. 根据 actor/channel 得到授权资料范围；过滤撤销和不允许访问的版本。
2. 标准化问题、中文分词、术语和别名展开；保留原始问题，不能改写掉否定、人物或年代。
3. 并行逻辑召回知识点标题/别名与教材正文 FTS；初期两种均为本地索引。多路搜索可以在代码中合并，无须创建多个 Agent。
4. 教材比对以教材片段为主；问答可优先已审核知识点答案，但不得丢掉不同教材的冲突证据。
5. 版本/权限过滤必须在最终 topK 前参与查询，避免先截取全局结果再过滤导致合法资料消失。
6. 合并重复与重叠结果、保留不同来源的必要证据，生成最多 8 条短摘录。
7. 如果无命中且预算允许，用标题别名或一次受限查询改写重试。第 5 阶段可加语义召回和融合排序；仍执行相同权限及预算。
8. 最终无命中返回空 hits；不调用模型编造一个“检索结果”。

FTS 初期内部候选上限 40；阶段 5 若增加语义召回，每路可取 20 合并后不超过 40。数字为可调初始配置，用真实评测确认，不作为准确率保证。

## 4. get_knowledge_point：已知题目，直接取答案

```ts
getKnowledgePoint(ctx, {
  pointId: string;
  answerVersion?: number; // 当前练习绑定时必须指定；问答默认最新可用版
});
```

返回：知识点名称、别名、答案版本、审核状态、逐条答案要点和 evidenceIds。用户个人状态默认不附带；通过获准的学习服务单独获取。旧版读取保留历史用途标记，不能将 superseded 答案冒充最新。

典型场景：今天复习的是 `point-demo-008`，就按 ID 读取。系统已经知道题目，无须让模型猜关键词重新在三本书里找一遍。

大答案返回摘要与要点 ID，在上下文构建阶段分批读取/反馈，不能单个工具返回绕过总预算。不存在/不可见的 ID 不回退到“最相似的另一道题”并冒充同一题。

## 5. get_source_excerpt：读取真实依据

```ts
getSourceExcerpt(ctx, {
  chunkIds: string[];      // 单次最多 3 个不可变片段 ID
  neighborDepth?: 0 | 1;   // 默认 0；需要上下文再取前后相邻片段
});
```

返回：原文、书名/版本、章节、页码锚点、文字哈希、审核/疑难状态和可访问的原件定位路由。临时下载 URL 在用户打开原件时由独立鉴权接口生成，不长期写进答案引用。

规则：只扩展同一资料版本/part 的合法相邻片段；跨页依靠已记录 anchors，不猜原书页码；不得通过 neighborDepth 绕过权限或总量限制。结果超预算时返回有界片段与 `truncated`/后续定位信息，不静默声称原文完整。

例子：检索摘录显示“具体包括以下四点”，调用回读取得列表后半段，避免只拿到其中两点就形成不完整答案。

## 6. get_related_points：关系与局部图谱

```ts
getRelatedPoints(ctx, {
  pointId: string;
  relationTypes?: ('contains' | 'prerequisite' | 'contrast' | 'confusable')[];
  depth?: 1 | 2;           // 默认 1
  limit?: number;          // 默认 20，图谱最多 50 节点/100 边
  cursor?: string;
});
```

只返回授权范围内、已确认的节点摘要与关系；图谱编辑页面另用候选关系接口。节点即使可见，隐藏来源不能通过关系标题泄露。个人学习状态根据 channel/角色另行附加，群聊不返回。

此工具帮助“这个概念容易与什么混淆”；不能因为图上连着，就把相邻节点的内容当作本题答案。

## 7. 学习查询与知识检索分工

| 用户问题 | 调用服务 | 不需要做什么 |
|---|---|---|
| “教育目的是什么意思？” | search → point / excerpt → 回答 | 不加载所有学习历史 |
| “今天该复习什么？” | list_due_points | 不全文搜索教材 |
| “这一题我漏了哪些点？” | 已绑定 point + answerVersion + evidence → feedback | 不重新选择另一套答案 |
| “这个知识点和什么有关？” | get_related_points | 不把全图放入上下文 |
| “给我随机抽一道” | 抽查服务从获准学习范围抽样 → get_knowledge_point | 不让模型随意捏造题目 |

`list_due_points(ctx, {cursor, limit})` 默认 5、最大 20 条，仅标题/原因/日期；返回总数和下一页游标。`get_learning_summary` 返回计数和最多 5 条摘要；完整 dashboard 不进入 prompt。

## 8. 五条端到端流程

### A. 日常学科问答

问题 → 身份/范围确认 → `search_knowledge(qa)` → 按候选读取知识点或原文 → 去重与预算 → 模型回答 → 后端校验引用 ID → 展示资料名称与页码。

命中未审核资料时标“转写待核对”；全部无命中时明确没有找到教材依据，可以给单独标注的通用说明或请用户补充知识名称，不伪造引用。

### B. 图片校正

原图 → 两次 OCR 与疑点 → 每个候选知识条目调用 `search_knowledge(photo_check, textbook_chunks)` → `get_source_excerpt` → 对照原稿和教材 → 校正草稿 → 人工核对 → 绑定稳定知识点 → 羊羊确认遗忘事件。

一张图包含很多知识点时拆成独立条目任务，最后以分页草稿展示；每项各自有预算，不把所有图片和整本书一起交给模型。

### C. 背诵反馈

到期/主动选择/随机抽查 → `get_knowledge_point` → 保存本次答案和依据版本快照 → 羊羊作答 → 按要点有界比对 → 返回遗漏/冲突/不确定及证据 → 羊羊自评 → 排程服务更新。

检索得到的段落不能直接提升为审核答案。没有 reviewed 答案则降级结构反馈，不能凭模糊相似度判错。

### D. 图谱复习

搜索或今日任务定位 point → `get_related_points` 加载一跳 → 点击节点按需读取详情 → 隐藏答案开始回忆 → 走同一背诵反馈与自评流程。节点展开和资料浏览不记录为复习完成。

### E. 管理员查看

管理员问今日情况 → 学习摘要（只读）→ 需要时分页任务摘要；管理员问教材知识 → 与羊羊共用授权知识检索。管理员不能通过工具调用保存羊羊自评或借正文指令取得写权限。

## 9. 失败、引用与版本边界

- 索引尚未构建与真正无命中分别展示；旧活动索引存在时可继续读旧版并标明，不混合半成品新版本。
- 语义服务不可用时降级本地 FTS；本地索引也不可用则说明暂不能查询资料。
- 模型不可用时，可展示真实摘录及其状态，不输出虚构的综合答案。
- 引用必须来自本次可见证据或本题固定证据快照，引用文字/位置由后端解析；模型不得自由生成书名页码。
- 发现引用 ID 无效时最多一次受限修复；仍失败退回可读原文和不足说明。修复属于同一预算，不另开无限循环。
- 引用格式合法不等于答案推理正确，语义支持关系仍需要评测与抽查。
- 学科资料中的文字只作数据，不能改权限、预算、确认状态或工具参数白名单。
- 内容修订、权限变动、索引版本变化使相关缓存失效；缓存键包含授权范围版本、purpose、query 与 indexVersion。

## 10. 用户可见解释与研发观测

网页提供“查看依据”，显示书名、章节、PDF 页码、原文与核对状态；不默认把 SQL、token、内部评分暴露给羊羊。没有资料支持时直接说明。

开发日志记录检索目的、命中 ID、耗时、索引版本、是否截断、模型输入预算、无命中/故障分类。不在普通日志保存原始照片、完整私聊或原文大段内容。

验收必须覆盖：标题不含关键词但正文有答案；同义问法；OCR 错字；两字术语；跨页列表；版本冲突；未审核资料；授权外 ID；1,000 条待办；来源页码；模型不可用；旧反馈引用不变。评测指标与分阶段出口见主设计文档。
