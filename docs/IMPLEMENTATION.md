# 实现进度（MVP-0）

## 已可运行

- 本地数据存储：首次运行自动生成 `.data/review-assistant.json`，后续复习与作答都会持久化。
- 今日计划：优先到期复习，再补薄弱点，最后引入新知识点；每日默认最多 5 项。
- 主动回忆：每项任务要求先作答，再用“完全想不起来 / 想起来很吃力 / 基本掌握 / 很熟练”自评。
- 调度：为未来 `ts-fsrs` 保留了独立调度器接口；当前使用可解释、已覆盖单元测试的四档间隔策略。
- 主观题反馈：`FeedbackService` 是渠道无关的统一入口。Web 和飞书都会先持久化 `feedback_job` 与关联 `answer_feedback`，再异步生成结构性提示；状态为 `queued / running / succeeded / failed`，并保存幂等键、模型/提示词版本、资料快照和错误码。服务启动时会续跑遗留的 `queued` 任务；遗留的 `running` 任务会记为 `failed / worker_interrupted`，不自动重放，以免重复调用模型产生费用。
- 前端：单页、移动优先，并针对 iPad 横竖屏做了响应式布局；可作为 PWA 添加到主屏幕。

## 等待资料或配置后接入

- `DocumentParser`：MinerU 主解析和 PaddleOCR 失败页回退。
- 有依据批改：接入已审核资料块、评分量表、结构化 schema 校验和答案证据引用；当前模型仍只提供无评分的结构性建议。
- 权威知识库：解析出的知识点先进入草稿状态，人工审核后才能进入出题和检索。
- 正式 FSRS：接入 `ts-fsrs` 并从当前调度器迁移已有复习状态。
- PostgreSQL / Redis：在多端同步、大规模异步解析或需要跨进程队列时升级；当前单机单用户阶段使用本地持久化任务状态。

## 关键不变量

- PDF 原文件不可被解析流程覆盖。
- 未人工审核的材料不可作为“标准答案”或评分依据。
- 模型证据不足时只给建议，不改写掌握度。
- 渠道层不直接调用模型；Web 和飞书只通过 `FeedbackService` 创建、处理和读取反馈任务。
