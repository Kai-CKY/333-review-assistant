# 飞书机器人首测与限定群测

## 多人群聊

群内支持文字、图片和图文消息。图片通过原消息的资源接口下载（需 `im:resource`），每条最多 3 张、每张最多 8 MB，支持 PNG/JPEG/WebP/GIF。当前轮传入原图进行识别，历史仅保存文字回复，不自动入库。

输入 `/上下文` 查看本群上下文状态；输入 `/重置上下文`（或 `/reset`、`重置上下文`、`清空上下文`）清空全群共用的最近对话。保留成员称呼，不删除飞书聊天记录或学习记录。这些指令不调用模型。每次模型请求包含系统提示、成员称呼、最近 12 轮已处理对话和当前输入，不自动补拉机器人离线期间的群历史。

执行 `node scripts/configure-group-chat.mjs oc_<群 ID>` 可启用指定群的自然语言对话。运行 `npm run feishu:update` 为现有应用补充 `im:message.group_msg`、`im:message.group_at_msg:readonly` 和 `im.message.receive_v1` 订阅，再重启机器人。群消息权限由飞书应用授权；本地程序只处理指定群。

群内每个人可以发送“我是小陈”或“我是羊羊”介绍自己，称呼按各自发送者 ID 持久化。机器人会读取成员显示名，并保存最近 12 轮群对话，让两人的发言有共同上下文。群聊使用独立模型提示词，不把私聊档案或单人学习记录带进群；当前群聊提供对话与学习建议，答题评分及学习记录写入仍走原学习流程。

本项目的飞书接入是“自建应用 + 机器人 + Node SDK 长连接”。飞书只作为渠道入口；学习计划、答案保存和间隔调度仍复用项目的核心服务。

## 账号归属

运行 `npm run feishu:create` 后，**扫描并确认二维码的飞书账号及其租户**决定应用归属，不受电脑浏览器中另一个已登录账号影响。

建议在手机飞书中先切换到目标账号，再扫描二维码。授权确认页会显示当前账号和租户；发现不对时直接取消，不要提交。创建后也可用该目标账号登录飞书开放平台，在“我的应用”中确认应用可见。首测脚本会把扫码账号的 `open_id` 写入本地 `.env.local`，机器人只响应该账号的私聊。

## 创建与后台配置

1. 运行 `npm run feishu:create`，用目标账号扫描并确认。凭据会写入 Git 忽略的 `.env.local`，脚本不会打印 App Secret。
2. 在新应用的飞书开放平台后台确认：
   - 应用能力包含机器人。
   - 私聊首测权限包含 `im:message:send_as_bot`、`im:message.p2p_msg:readonly` 与 `im:message.reactions:write_only`。一次性限定群测还需要 `im:chat.members:read`，仅用来确认指定账号是否已加入指定群。
   - **事件与回调 → 事件配置**：选择“使用长连接接收事件”，确认 `im.message.receive_v1`。
   - **事件与回调 → 回调配置**：选择“使用长连接接收回调”，确认 `card.action.trigger`。
   - 创建测试版本/按租户后台流程发布，并把可用范围限制为目标测试账号。
3. 运行 `npm run feishu:enable`（或将 `.env.local` 中的 `FEISHU_ENABLED=false` 改为 `true`）。
4. 运行 `npm run dev:feishu`。日志出现 `Feishu bot connected as ... (private test mode).` 后再开始聊天测试。若本机 3333 已被占用，`npm run feishu:enable` 会为首测默认设置 `PORT=3334`。

若后台在切换长连接时提示尚未建立连接，可先完成第 3、4 步让本机机器人连上，再回到后台重试设置。

若应用已经创建、只是要补“收到消息后的绿色 DONE 对勾”，运行 `npm run feishu:update`。脚本会输出授权链接并导出 `.data/feishu-update-qr.png`；必须使用**原应用归属账号**扫码确认，确认后重启机器人。这个 DONE 表情表示机器人已经收到并开始处理，不等同于飞书的真实已读状态。

## 一次性限定群测（羊羊）

这是一个窄范围的入群触发测试，不会把机器人开放为通用群聊助手：它只监测一个精确的 `oc_...` 群聊 ID、一个精确的 `open_id`，并且只发送一次固定的“今日学习情况”提问。

1. 确认机器人已经在目标群里。运行 `npm run feishu:update`，由**原应用归属账号**扫码确认，将 `im:chat.members:read` 权限发布到测试版本；如果权限尚未生效，成员检测会被飞书拒绝。
2. 执行 `npm run feishu:group-test -- oc_<群聊 ID> ou_<羊羊的 open_id>`。它只更新本机 Git 忽略的 `.env.local`：启用飞书和群测，并写入该群 ID 与准确的目标账号；不会显示或修改现有凭据。只有在已确认羊羊就是当前绑定测试账号时，第二个参数才可明确写成 `@tester`。
3. 不要按昵称或当前测试账号推断羊羊身份；必须使用她准确的 `FEISHU_GROUP_TARGET_OPEN_ID=ou_...`，然后启动或重启机器人。
4. 运行 `npm run dev:feishu`，再将羊羊加入该群。机器人会每约 5 秒确认一次成员列表；识别到目标账号后，向这个群发送一次“今天的学习情况怎么样？”的固定提问。即使进程重启，也会保留已发送标记而不重复打扰。
5. 测试结束后，将 `.env.local` 中的 `FEISHU_GROUP_TEST_ENABLED` 改回 `false` 并重启机器人。

限定群测不会读取群消息、按昵称猜测身份、处理其他群，或把群内回复写入学习记录；正常学习交互仍只在绑定账号的私聊中进行。

## 首测流程

在目标账号与机器人私聊：

1. 发送“你好”验证快速自然语言回复，并确认原消息出现绿色 DONE 对勾；再发送“今天学什么”获得今日任务卡。
2. 点击“开始回忆”，或在没有进行中题目时输入 `/开始 1`。
3. 可发送“给我一个提示”或 `问：这个概念怎么区分？` 继续陪练；这些内容不会保存为答案。
4. 发送 `答案：你的回答` 明确提交。明显的陈述性答案也可直接发送；短问句会先弹卡片确认，普通问候和学习状态沟通不会误存。
5. 点击四档自评之一：完全想不起来、想起来很吃力、基本掌握、很熟练。
6. 若已配置豆包，确认会收到一张“豆包提示”卡；它只提供结构性建议，不会自动评分或改变排程。
7. 直接发送“我今天完成了教育学第一章，还刷了 30 道题”，确认无需等待模型便收到“已记入 · 最近完成”卡；用 `/记录` 查看，必要时点击“撤销这条”。这类自报只进入复盘备案，不改变掌握度或复习日期。
8. 确认机器人回复下次复习日期；刷新本地 Web 页面，确认掌握度、复习闭环次数与自报备案数量分别显示。

可用命令：`/今日`、`/薄弱`、`/进度`、`/记录`、`/继续`、`/取消`、`/帮助`。也可以用 `/记录 已完成的内容` 明确写入一条备案。

## 安全边界

- 首测只响应绑定账号的私聊；不处理群聊、附件或主动提醒。
- App Secret、模型 API Key 和答案正文不会写入日志；`.env.local` 不纳入 Git。
- 卡片重复点击和平台重投会通过会话状态与来源 ID 去重，避免重复写入复习记录。
- 任务完成自报使用独立记录并可撤销；它不会写入答题记录、四档自评或间隔复习排程。
- 还未配置模型时，机器人只保存答案并要求用户自评，不会伪造 AI 评分。
- 模型只能输出只读意图；提交答案、开始建议任务、取消和四档自评都由代码规则或卡片确认执行。
- 当前有题目进行时，新任务不会覆盖它；需要先完成或输入 `/取消`。

## 豆包 Seed 2.1 Turbo

运行 `npm run ark:configure` 后，在本机终端粘贴 **新的、未泄露的** Ark API Key；输入不会回显，脚本会把密钥、安全的 Ark Base URL 与模型 ID 写入 Git 忽略的 `.env.local`。随后运行 `npm run ark:verify` 分别验证受限意图、自然对话和结构性反馈。命令只输出模型 ID、意图和字符数，不输出 API Key 或模型正文。

默认公共模型是 `doubao-seed-2-1-turbo-260628`。如果在方舟控制台创建了专用推理接入点，应将 `.env.local` 中的 `ARK_MODEL_ID` 改为该接入点的 `ep-...` ID。模型反馈仅在用户私聊答题后发送，且不会参与四档自评或间隔复习算法。

`ARK_TIMEOUT_MS` 默认设为 `45000`，以容纳首轮模型响应；超时或上游错误只会让该次提示失败，不会重试、重复计费、回滚答案或影响自评。常见问候与明确完成汇报完全不调用模型；普通无状态闲聊只调用一次模型，收到消息后则先用 DONE 对勾即时确认。Seed 2.1 Turbo 请求会显式使用 `thinking: { type: "disabled" }`，避免简单交互落入默认高强度思考；若以后确有复杂推理需求，可把 `ARK_THINKING_TYPE` 设为 `enabled`。

方舟的低延迟服务档可通过 `ARK_SERVICE_TIER=fast` 选择，但可能需要单独开通和计费，因此默认不开启。

参考：[方舟 OpenAI 兼容快速开始](https://www.volcengine.com/docs/82379/1795150) 与 [方舟模型列表](https://www.volcengine.com/docs/82379/1799865)。
