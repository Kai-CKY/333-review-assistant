# 图片知识任务流式修复：本地交付说明

日期：2026-09-28。基线：GitHub `origin/main` 的 `265e9066d7ee251f2aba2049b1da4ac3efe03700`，本地分支 `codex/image-streaming-fix`。

## 本次修复范围

本次实施图片 OCR、合并/修订、联网核验的请求链路和错误诊断。群聊严格介入策略、多人身份与会话记忆仍属于此前设计方案，本次补丁没有实现它们。原开发目录中已有的未提交改动已保留，修复位于独立工作区。

## 根因与证据边界

- 代码中的图片长 JSON 请求和联网核验请求此前都采用非流式；核验还将最多 40 条内容放进一个请求，共享搜索次数和输出预算。
- `ArkFeedbackProvider` 的超时归一化存在 60 秒上限，使 `.env.local` 中的 `180000` 实际被钳制为 60 秒。单改环境变量不能解决这个问题。
- 线上反馈中非流式 180/600 秒失败、流式约 110 秒成功，支持长时间无响应字节导致连接问题的判断。本地没有接触线上网络设备，不能断言具体哪一层断开连接。
- 错误归一化原先读取有限的 `message` 白名单，而 `ArkFeedbackError` 的稳定标识位于 `code`。异常未打印，原始原因因此难以追踪。
- 6 次搜索不等于只能核验 6 条，12000 输出 token 也不意味着每次必然截断；问题是整稿共享预算、长输出链路及失败处理缺少边界。

## 实现行为

1. 公共 SSE 解析器支持 UTF-8 跨块、LF/CRLF、多行 data、注释、事件大小/总大小限制、超时取消与提前关闭。半份事件和缺失终止标记不能作为成功结果。
2. `PhotoKnowledgeModel.json()` 开启流式，覆盖两次 OCR、align、revise、教材比对。Chat Completions 拼接增量内容，要求结束原因及 `[DONE]`，收集最终 usage。结构化任务要求 `finishReason === 'stop'`。短普通对话保持原调用方式。
3. `ArkKnowledgeSearch` 使用流式 Responses API，默认每批 8 条，顺序处理；完整 `response.completed` 是终止成功依据，不等待服务端关闭连接。每批独立享有最多 6 次工具调用与 12000 输出 token。
4. 单批失败最多额外重试两次，限于超时、网络错误、部分结果不完整、无效 JSON、429 和 5xx 等可恢复原因。退避与 Retry-After 有上限，所有批次和重试共享整轮时限。鉴权和配置错误不重试。
5. 批次失败保留已完成批次的结果；后续遇到鉴权/配置错误会停止新请求，保留已有成果，失败或未执行条目标为待核验。来源只能使用该批真实工具输出/引用注释中的 URL，条目 ID 必须一一对应，空文本和伪造来源不能变成已核验。
6. 保留批次、尝试次数、已知 response ID、真实工具调用与已知 usage。缺失 usage 会明确标记，成功批次调用数与所有已知尝试用量的统计口径分别标注。
7. 服务层记录草稿 ID、阶段、具体错误码、耗时、错误消息和堆栈；过滤密钥及图片 data URL。失败保留已有原图资产和 OCR 结果。草稿会提示核验未全部完成，仍需原有身份、会话、版本和送达校验后人工确认。
8. 校验模型的条目、差异和检索词结构，避免字符串 `differences` 或空条目导致草稿生成后无法送达；这类异常使用具体错误码保留在草稿中。

## 配置

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `ARK_TIMEOUT_MS` | `180000` | Chat 请求总时限，包含流读取；允许范围 1 秒至 10 分钟 |
| `ARK_VERIFY_BATCH_SIZE` | `8` | 每批核验条数，允许 1 至 40 |
| `ARK_VERIFY_TIMEOUT_MS` | `300000` | 每次核验请求时限，最大 10 分钟 |
| `ARK_VERIFY_TOTAL_TIMEOUT_MS` | `1800000` | 整轮联网核验含重试的时限，最大 60 分钟 |

线上 `.env.local` 已由线上排查方设为 `ARK_TIMEOUT_MS=180000`。部署时保留线上实际模型、密钥与环境覆盖值，不用 `.env.example` 覆盖它。新增核验配置未设置时使用代码默认值。

## 使用效果与上线验收

- 发送经现有路由接受的图片：两次 OCR 与合并流式生成，40 条知识默认分为 5 批核验，完成后送达待人工确认草稿。
- 如某一批 8 条持续失败，其余 32 条仍可形成有证据的结果；失败 8 条显示待核验，不会自动入库。授权人可核对后使用原有“确认已核验部分”命令。
- 中途断流且没有完整结束标记：明确报错/待核验，不将残缺 JSON 当作成功，也不清除已保存的原图与前两轮 OCR。

由上线方执行最终验收：先通过 CI 容器构建与 JSON/SQLite 冒烟测试；保留线上环境和数据快照，再用新镜像验证既有草稿的“重新核验”会生成新版本并完整送达；另发一张测试图验证完整流程。核对来源和文字后再由授权人确认。自动离线测试尚不能证明真实 Ark 服务和飞书送达在当前线上环境一定成功。

## 已知边界

- 未实现批次持久化断点或重启续跑；手动“重新核验”会再次查询所有待核验输入批次。
- 长任务仍沿用现有群会话队列，会占用该会话的处理时间；没有改成后台任务或新增取消接口。
- 流式请求仍受单请求/整轮时限、服务端生成能力、网络断流与供应商限流约束，不能保证每份图片必定完成。
- 此补丁不代表此前“群里每句都回、把其他成员当羊羊、忘记上一题”的问题已经修复。
